# 2. Prompts

## 2.1 Prompt Used to Define Dialogue Metrics

You are an expert in conversational text-to-SQL agents that engage in dialogues with users to help them access a database.

Each dialogue captures what the user observes when interacting with the conversational text-to-SQL agent to retrieve data from the database.  A turn is either a user turn or a system turn, each composed of NL sentences, called utterances, produced by the user or by the system.  An interaction is a sequence of two or more turns, starting with a user turn, ending with a system turn, and alternating between user and system turns.  A dialogue is a sequence of interactions.

The utterances in a user turn express:  
– A greeting, that optionally signals the start of a dialogue or an interaction;  
– A question, that specifies a database request;  
– A partial question, that partially specifies a database request and that must be expanded into a (complete) question using the dialogue context;  
– A context modification, that modifies the following questions in the dialogue;  
– A clarification, that responds to a request from the system.   
The utterances in a system turn express:  
– An acknowledgment, that signals that the system understood the user;  
– A response, that describes data retrieved from the database;  
– A request, that asks the user to clarify his utterance;  
– An error message, that signals when the user’s utterance cannot be processed.

Please suggest what properties a dialogue must have. An example is the dialogue's naturalness, which reflects how well it mimics a real-world interaction between a user and a conversational text-to-SQL agent.  
(Response)  
The most important properties of a conversational text-to-SQL dialogue can be summarized as follows:

| Property | Why it is important |
| ----- | ----- |
| **Naturalness** | The dialogue resembles a realistic interaction between a user and a conversational database assistant. |
| **Coherence** | The conversation is logically connected, with each turn following naturally from the previous ones. |
| **Context Management** | The system correctly maintains dialogue state, including previous questions, constraints, and context modifications, enabling natural follow-up questions. |
| **Groundedness** | User requests and system responses are consistently grounded in the database schema and contents. |
| **Correctness** | The system accurately interprets the user's intent and returns answers that faithfully reflect the results of the corresponding SQL query. |
| **Clarification Quality** | When a request is ambiguous or incomplete, the system asks clear and focused clarification questions that efficiently resolve the ambiguity. |
| **Efficiency** | The user's information need is satisfied with as few interactions as possible while maintaining accuracy. |
| **Completeness** | Every user request is fully resolved, either by providing the requested information or by explaining why it cannot be answered. |

Among these, **Naturalness**, **Context Management**, **Groundedness**, and **Correctness** are arguably the four defining properties of conversational text-to-SQL systems. Naturalness ensures that the dialogue resembles human conversation, Context Management enables multi-turn interactions through references and follow-up questions, Groundedness guarantees that interpretations are tied to the database schema and data, and Correctness ensures that the retrieved information accurately answers the user's request. Together, these properties distinguish conversational text-to-SQL agents from traditional single-turn text-to-SQL systems.

## 2.2 Prompt Used to Evaluate Dialogues

You are an expert in conversational text-to-SQL agents.

Your task is to inspect the list of dialogues passed as an attachment and classify each dialogue according to the following criteria:

Naturalness: The dialogue resembles a realistic interaction between a user and a conversational database assistant. The naturalness score should be measured on an integer scale from 1 to 5\.

Coherence: The conversation is logically connected, with each turn following naturally from the previous ones. The coherence score should be measured on an integer scale from 1 to 5\.

The list of dialogues is a json file. Each dialogue has the following structure:

| experiment\_id | The dialogue id. |
| :---- | :---- |
| total\_expected\_interactions | The total number of interactions in the dialogue. |
| Interactions | The list of interactions in the dialogue, numbered 0, 1, 2, …, n. |
| i | The interaction number. |
| interaction\_id | The interaction id. |
| speaker | "User". |
| utterance | A natural language user question, which can be partially formulated. |
| Intention | The intention of the user question, which is a natural language sentence fully defining the user question. |
| ground\_truths |  |
| tables\_from\_schema\_linking |  The list of tables used in the ground-truth SQL query. |
| golden\_sql | The ground-truth SQL query responding the user question. |

The utterance key defines the user turn and the golden\_sql key defines the system turn, expressed as an SQL query.

You should output a table with the following columns:

experiment\_id: the value of the experiment\_id key identifying the dialogue.  
Naturalness: the naturalness score of the dialogue.  
Coherence: the coherence score of the dialogue.

**Naturalness (Score: 4/5 across all experiments)**

* **Realistic Analytical Flow**: The user turns closely mimic a data analyst performing an iterative exploratory data analysis (EDA) session on a relational database.  
* **Domain-Specific Phrasing**: Utterances use practical, human-like prompts ("Can you order those...", "Do any estuaries share...", "Which of these...").

**Evaluation Overview**  
**Experiment 1:** Excellent logical flow throughout 10 turns. Phrasing is slightly formal ("at-or-above-sea-level circuits"), but maintains strong context across all interactions.

* **Experiment 2:** High naturalness and flawless coherence. The user progressively refines criteria (filtering by points, status, and comparing results with standings) in an authentic, step-by-step exploration.

* **Experiment 5:** Strong logical thread tracking drivers across lap times and pit stops. Phrasing is occasionally mechanical ("resulting nationality groups"), but the dialogue remains coherent.  
* **Experiment 6:** Clear state tracking and contextual flow. Has a minor redundant nationality check on a pre-filtered British subset, but overall maintains high conversational quality.
